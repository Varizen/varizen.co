# ZLET
## Universal Global Wallet, Payments & DeFi Sandbox

Build **Zlet**, a globally oriented, sandboxed financial application that brings together the user's **mobile money, payment wallets, card wallets, digital wallets, stablecoins, cryptocurrencies, DeFi protocols and supported payment networks** into one unified interface.

Zlet is **not a conventional bank**.

The fundamental product philosophy is:

> **One screen for all the money the user is actually allowed to control.**

The user should not have to jump between:

- Google Pay
- Apple Pay
- Samsung Wallet
- regional mobile financial services
- mobile wallets
- payment apps
- prepaid wallets
- merchant wallets
- crypto wallets
- stablecoins
- DeFi protocols
- exchanges
- payment cards
- loyalty/payment balances
- supported digital assets

Zlet should provide one intelligent control layer over them.

---

# 1. Core Product Concept

Zlet is a **Universal Financial Interface**.

Instead of replacing every financial provider, Zlet connects to them through the appropriate official mechanism:

```text
                    ZLET
                      │
       ┌──────────────┼──────────────┐
       │              │              │
   PAYMENTS         MONEY           DEFI
       │              │              │
 Mobile Wallets   MFS / Wallets   DEX
 Apple Pay        Prepaid         Lending
 Google Pay       Stored Value    Liquidity
 Samsung Wallet   Payment Apps    Staking
 Cards*           Remittance      LP
       │              │              │
       └──────────────┼──────────────┘
                      │
               Unified Interface
```

`*` Cards may be represented through supported wallet/payment integrations; Zlet must not pretend to replace card-network or bank infrastructure where it cannot legally do so.

---

# 2. Non-Bank Principle

Zlet must **not become a disguised conventional bank**.

Do not build a fake banking ledger and pretend that Zlet itself holds deposits.

Instead:

- Native balances remain with their providers.
- Native wallets remain with their providers.
- Blockchain assets remain in the user's wallet or approved custody arrangement.
- Payment credentials remain within the applicable secure wallet/tokenization system.
- Zlet maintains only the minimum data required for orchestration, authorization, transaction history and user experience.

Where a jurisdiction requires licensing for custody, money transmission, stored value, exchange, brokerage, remittance or other regulated activity, Zlet must use an appropriately licensed provider or structure the feature accordingly.

**Never bypass licensing requirements.**

# 40. Sandboxed Architecture

Zlet must behave like a financial version of an **AIBrowser sandbox**.

The AI operates inside a controlled environment.

It receives only the capabilities granted to it.

```text
Zlet AI
   │
   ▼
Permission Sandbox
   │
   ├── Wallet Read
   ├── Payment Prepare
   ├── Payment Execute
   ├── Exchange Quote
   ├── DeFi Simulation
   ├── DeFi Execute
   └── Transaction History
```

No unrestricted operating-system access.

No unrestricted browser access.

No unrestricted filesystem access.

No unrestricted financial credentials.

- Seed phrases

- OAuth client secrets

# 42. Native Data Principle

> **Connect. Orchestrate. Don't unnecessarily relocate.**

Crypto → remains in user's wallet.

DeFi position → remains on-chain.

Zlet stores the minimum operational metadata required.

- Risk

**Unavailable**
