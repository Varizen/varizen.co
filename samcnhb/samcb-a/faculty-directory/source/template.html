IT handover

Designed for a browser-only draft workflow. A secure production deployment requires an authenticated backend and institutional policies.

1. Verify before provisioning

  1. HR checks every current employee, department, designation and actual joining date.
  2. IT confirms ownership and availability of samcbbd.email. Proposed aliases are not proof that the domain or mailbox exists.
  3. IT checks collisions against its authoritative account directory, not just this snapshot.
  4. Verify portrait identity separately if photos will be used on staff accounts.

2. Credentials

The requested default is NoPass3!, with a mandatory change at first login. Because a shared default is insecure, IT should replace it with a unique, securely delivered temporary credential and enforce reset plus MFA where available.

No password is stored in faculty records or exported joiner requests.

3. Maintain this file

  • Review: correct phone, joining/reference dates, proposed ID/email, or mark verification. Edits stay only in this browser's local storage.
  • Export: download filtered or complete CSV/JSON for handover. Keep controlled backups.
  • Rebuild: run python build.py in this folder after updating the public archive. Rebuilding replaces generated records, not your exported HR system.
  • Publish: host index.html on an approved internal server. Configure an authenticated form endpoint before soliciting personal information online.

Production recommendation

For real IT support, connect the joiner form to your existing authenticated ticketing system. Validate HR authorization server-side, encrypt data in transit and at rest, restrict access, log account provisioning, and define retention/deletion rules.
