Build **ZenCalendar**, an ultra-light, beautiful, universal AI calendar application and sandbox.

### 1. Core concept

ZenCalendar is **one intelligent calendar for every calendar account**.

Connect:

- Google Calendar
- Microsoft Outlook / Microsoft 365 Calendar
- Apple/iCloud Calendar
- CalDAV
- Exchange
- Other supported calendar providers

Present everything in one unified calendar while keeping the actual events and calendar data in their **native providers**.

**Do not migrate or unnecessarily duplicate the user's calendar data.**

ZenCalendar is an intelligent **calendar client + AI agent + scheduling sandbox**.

### 5. Calendar Agent Mode

Create an optional **AI Calendar Agent**.

Instead of manually managing events, the user can say:

> **"Handle my calendar."**

AI analyzes the calendar and presents:

**Today**
- 4 meetings
- 1 conflict
- 2 preparation tasks

**Needs me**
- Accept invitation from John
- Choose time for project meeting

**AI can handle**
- Reschedule 3 meetings
- Send 2 scheduling proposals
- Add 30-minute preparation blocks

**Conflicts**
- Two meetings overlap at 3:00 PM

The user can approve individual actions or approve a group.

ZenCalendar should intelligently calculate suitable meeting times.

Consider:

- Existing events
- Working hours
- Holidays
- Time zones
- Attendee availability
- Meeting duration
- Preferred meeting windows
- Focus time
- Travel time
- Existing commitments
- User-defined priorities

Example:

> "Schedule a 45-minute meeting with Sarah and John next week."

**Best options**

Tuesday 10:00–10:45  
Wednesday 14:00–14:45  
Thursday 11:30–12:15

Then allow:

with one tap.

---

### 7. Scheduling sandbox

This is the key differentiator.

Before making real calendar changes, AI works inside a **sandbox calendar environment**.

Example:

User says:

> "Rearrange tomorrow so I have a 3-hour uninterrupted work block."

ZenCalendar creates a **proposed schedule** without changing the real calendar.

Display:

### Proposed Schedule

09:00 — Existing meeting  
10:00 — Existing meeting  
11:00 — Move internal meeting → 15:00  
12:00 — Lunch  
13:00 — Focus block  
16:00 — Existing meeting

Actions:

**Apply changes**

**Modify**

**Discard**

The real calendar remains untouched until the user approves.

---

### 8. Simulation mode

Allow the user to ask:

> "What if I add a 2-hour meeting tomorrow?"

> "What if I move this meeting to Friday?"

> "What would my week look like if I blocked every morning for deep work?"

ZenCalendar should simulate the change in the sandbox and show the consequences.

Nothing is written to the native calendar until approved.

---

### 9. AI action permissions

Create a clear permission system:

**Read**
→ AI can inspect calendars.

**Suggest**
→ AI can propose changes.

**Prepare**
→ AI can create sandbox changes.

**Act**
→ AI can modify the real calendar.

**Communicate**
→ AI can send scheduling messages/invitations.

Sensitive actions must require explicit permission unless the user has previously granted that authority.

---

### 10. Calendar sandbox architecture

Treat the sandbox as an isolated execution environment.

AI should never receive unrestricted access to the user's entire calendar infrastructure.

Capabilities should be explicitly granted:

```text
Calendar Sandbox
 ├── Read availability
 ├── Read events
 ├── Create proposal
 ├── Modify event
 ├── Cancel event
 ├── Create invitation
 ├── Send invitation
 └── Send scheduling communication
```

Every capability must be permission-controlled.

---

### 11. Native data principle

This is critical.

**Calendar data stays where it originally belongs.**

Google Calendar events remain in Google Calendar.

Microsoft events remain in Microsoft 365.

iCloud events remain in iCloud.

CalDAV events remain on the CalDAV server.

ZenCalendar should store only the minimum information necessary for:

- Synchronization
- Caching
- Search
- AI operation
- Local performance
- Sandbox proposals

Do not create an unnecessary centralized calendar database.

### 14. Email integration

ZenCalendar should work naturally with **ZenBox**.

Example:

An email says:

> "Can we meet Thursday afternoon?"

ZenCalendar can identify the request and propose suitable times.

The user can say:

> "Handle it."

AI checks availability, prepares a scheduling response and shows it before sending.

Likewise, calendar invitations arriving through ZenBox should appear intelligently inside ZenCalendar.

### 15. AI Browser-style sandbox

For scheduling websites or services that don't provide APIs, provide an optional browser sandbox.

The AI can interact with external scheduling systems **inside an isolated browser environment**.

The browser must not automatically gain unrestricted access to:

- Local files
- Passwords
- Cookies
- Personal browser sessions
- Other applications

Use explicit permissions and isolated sessions.

### 25. Provider abstraction

Use a clean adapter architecture:

```text
CalendarProvider
 ├── GoogleCalendar
 ├── MicrosoftGraph
 ├── AppleCalDAV
 ├── Exchange
 ├── GenericCalDAV
 └── OtherProvider
```

Do not scatter provider-specific code throughout the application.

---

### 26. AI provider abstraction

Do not lock ZenCalendar to one AI provider.

```text
AIProvider
 ├── OpenAI
 ├── Anthropic
 ├── Gemini
 ├── Local Model
 └── Enterprise Model
```

Allow organizations to control which AI provider processes calendar data.
