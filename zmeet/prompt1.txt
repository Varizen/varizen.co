Build **ZenMeet**, an ultra-light, premium AI meeting and live-session platform inspired by the best parts of Zoom, Google Meet, Microsoft Teams, and StreamYard — but substantially simpler.

The core idea:

> **Create a meeting, invite people, and let AI handle everything else.**

ZenMeet should support ordinary private meetings, business meetings, webinars, interviews, presentations, livestream-style sessions, and collaborative rooms.

---

## 1. Core concept

ZenMeet is a **universal AI-powered meeting room and live-session sandbox**.

Users can:

- Create a meeting
- Invite participants
- Join instantly
- Share camera
- Share microphone
- Share screen
- Share files
- Present slides
- Chat
- Record
- Transcribe
- Generate notes
- Stream publicly
- Host webinars
- Manage speakers
- Manage audience members

But the interface must remain **extremely simple**.

No unnecessary enterprise complexity.

---

## 2. Meeting types

When creating a session, allow:

### Private Meeting
Small group video/audio meeting.

### Business Meeting
Structured meeting with agenda, notes, actions and follow-up.

### Interview
Host + guest format with recording and AI interview assistance.

### Webinar
Host + speakers + audience.

### Live Show
StreamYard-style scene-based live production.

### Presentation
Speaker-focused presentation with slides and screen sharing.

### Workshop
Interactive meeting with collaborative tools.

### AI Session
AI participates as an assistant, moderator, note-taker or facilitator.

The user should be able to start with a simple:

**New Meeting**

and choose advanced modes only when needed.

# 4. AI Meeting Organizer

The defining feature is the AI meeting agent.

The user can say:

> "Organize a meeting with Sarah and John about the SAMC project."

AI should:

1. Check calendar availability.
2. Find suitable times.
3. Create the calendar event.
4. Prepare the meeting room.
5. Generate an agenda.
6. Draft invitations.
7. Send invitations after approval.
8. Prepare relevant documents.
9. Create the meeting automatically.

Integrate directly with **ZenCalendar**.

---

# 5. Meeting sandbox

Every meeting should have an isolated **Meeting Sandbox**.

The sandbox controls:

- Participants
- Microphones
- Cameras
- Screens
- Files
- Chat
- AI
- Recording
- Transcription
- Presentations
- Streaming
- Moderator permissions

The AI should never automatically gain unrestricted access to the host's computer.

---

# 6. AI permissions

Use a clear permission model.

### Observe

AI can listen to the meeting and understand context.

### Assist

AI can summarize, answer questions and identify tasks.

### Act

AI can perform meeting actions.

### Control

AI can manage participants and meeting settings.

### Broadcast

AI can operate live-production functions.

Every sensitive capability should be explicitly permission-controlled.

# 18. Secure meeting mode

Create:

## ZenMeet Secure Session

For confidential meetings.

Provide:

- Strong transport encryption
- Optional end-to-end encrypted meeting mode where technically supported
- Participant verification
- Session authentication
- Waiting room
- Host-controlled admission
- Recording restrictions
- Screenshot/recording warnings where technically feasible
- Secure file exchange
- Session expiration
- Device/session management

Do not make false claims about end-to-end encryption.

If a feature prevents server-side recording/transcription, clearly explain that limitation.

# 19. AI privacy boundary

Normal meeting:

AI can operate according to user permissions.

Secure meeting:

AI access must be explicitly authorized.

The user must be able to choose:

**AI OFF**

**AI ASSISTANT**

**AI NOTE-TAKER**

**AI FULL ACCESS**

Never silently send confidential meeting content to an external AI provider.

# 21. Native storage principle

Do not force all meeting data into ZenMeet storage.

Allow integrations with:

- User's cloud storage
- Organization storage
- Native provider storage
- Local storage
- Object storage
- S3-compatible storage

The user should control where recordings and files live.

ZenMeet should maintain only the metadata necessary to operate the service.

The meeting engine must prioritize:

- Low latency
- Stable audio
- Stable video
- Adaptive bitrate
- Network recovery
- Efficient bandwidth usage
- Fast room entry

# 35. Architecture

Use modular components:

```text id="d3phq9"
ZenMeet
│
├── Meeting Client
│
├── Room Service
│
├── WebRTC / Media Layer
│
├── Signaling
│
├── SFU / Media Infrastructure
│
├── AI Meeting Agent
│
├── Recording Service
│
├── Transcript Service
│
├── Live Production Engine
│
├── Scheduling Integration
│
├── Storage Adapter
│
└── Identity / Permissions
```

Use an SFU architecture for scalable multi-party meetings.

Keep media, signaling, AI, recording and storage logically separated.
